# maki_api_client (EXPERIMENTAL)
Contract for the Maki POS backend. This file is the single source of truth:
maki-fe and maki-mobile generate their API types from it, so update it in
the same commit as the handler change.

Business endpoints live under `/api/v1`. Errors always use the
`ErrorEnvelope` schema; clients switch on `error.code`, never on `message`.

`error.message` is written in the language of the `Accept-Language`
request header — Indonesian (`id`, the default) or English (`en`) — and
the response's `Content-Language` header names the one used. Clients show
their own translation of `code` when they have one, and fall back to
`message`.

**Signing in.** `POST /api/v1/auth/login` returns a 15-minute access token,
sent as `Authorization: Bearer <token>`, and a refresh token that lasts 30
days from its last use. The web app gets the refresh token as an
`HttpOnly` cookie that page scripts can't read; the Android app gets it in
the response body and keeps it in secure storage. Each refresh replaces
the refresh token; presenting one that was already replaced signs that
session out everywhere.

**Access.** Every signed-in user has a set of `permissions` (see
`GET /api/v1/me`). An endpoint under `/api/v1/outlets/{oid}/` first checks
that the user may act in that outlet — the Owner in any outlet, everyone
else only in their own — and answers 404 `outlet_not_found` otherwise,
the same as for an outlet that doesn't exist. It then checks the
permission the endpoint names, 403 `forbidden` without it. Endpoints for
the Owner alone answer 403 `forbidden` to anyone else.

**Lists** take `?page=` (from 1) and `?page_size=` (1–100, 20 by default)
and answer `{\"data\": [...], \"meta\": {\"page\", \"page_size\", \"total\"}}`.

**Rate limits.** Sign-in, password reset and email verification answer
429 `rate_limited` when hit too often, per IP address and per account,
with a `Retry-After` header and `details.retry_after` in seconds.
